# oes-babl-win: Windows 10/11

Нативный PowerShell-лаунчер Chrome на отдельном мониторе Virtual Display Driver (VDD). Без WSL, VM и X-сервера. Windows API вызывается через небольшой C#-модуль, который компилирует встроенный `Add-Type`; устанавливать .NET SDK не нужно. Linux-версия остаётся в `oes-babl` и `install.sh`.

**Статус:** реализация с автоматическими тестами; аппаратная приёмка VDD + Chrome + Google Meet ещё требуется. Нельзя считать этот проект подтверждённой заменой Xephyr по степени изоляции.

## Что именно изолировано

В Google Meet выбирайте **«Представить экран → Весь экран → именно монитор VDD»**. Окна на других мониторах не входят в его изображение. Выбор физического монитора или объединённого рабочего стола не даёт нужного результата.

VDD — обычный монитор Windows, а виртуальные рабочие столы — организация окон. Они **не являются границей безопасности**: уведомления, панель задач, закреплённые на всех рабочих столах окна и приложения, открытые на VDD, могут попасть в трансляцию. Буфер обмена остаётся общим. Скрипт перемещает принадлежащие ему окна Chrome, но не запрещает другим программам рисовать на этом мониторе.

При изменении рабочего стола или геометрии VDD скрипт останавливает свой Chrome. Проверка выполняется периодически, поэтому она **не гарантирует отсутствие отдельных нежелательных кадров**. Внешнюю запись, например OBS, скрипт не останавливает. Завершайте демонстрацию/запись **перед** закрытием Chrome, Ctrl+C и переключением рабочего стола.

В отличие от Linux-оригинала, создаётся **новый** user-data-dir. `-Profile 'Profile 1'` выбирает имя каталога внутри новых данных: существующие cookies, входы, пароли и расширения не переносятся. Это следует требованию уникального временного каталога, но не воспроизводит использование существующего профиля. Автоматическое копирование профиля не реализовано: шифрование Chrome и незавершённые записи делают такой перенос ненадёжным.

## Требования и совместимость

- Windows 10 1809+ или Windows 11, **x64**; интерактивная локальная сессия, физический основной монитор.
- Windows PowerShell 5.1+ (x64), Google Chrome, winget из Microsoft App Installer.
- VirtualDrivers Virtual Display Driver и Microsoft Visual C++ Redistributable x64.
- VirtualDesktopAccessor.dll (VDA) для автоматизации рабочих столов. DLL загружается установщиком.
- Интернет для установки; администратор для установки/включения драйвера и при необходимости VC++.
- Ежедневный запуск выполняется от обычного пользователя. ARM64, x86, Windows Server и RDP не поддерживаются этой сборкой.

Матрица **выбора** DLL, не обещание совместимости со всеми последующими накопительными обновлениями:

| Windows build | Выбранный релиз VDA | Режим |
| --- | --- | --- |
| Windows 10: 17763–19045 | 2019-windows10 | Только явно заданный MonitorOnly |
| 22621, UBR 2215–3084; 22631, UBR 2506–3084 | 2023-11-10-windows11 | Required, с проверкой API |
| 22621/22631, UBR ≥ 3085 | 2024-01-25-windows11 | Required, с проверкой API |
| 26100, UBR ≥ 2605; 26200 | 2024-12-16-windows11 | Required, с проверкой API |
| Другие сборки, включая ранние Windows 11 | Последняя известная DLL сохраняется, но не загружается | Только явно заданный MonitorOnly |

На 2026-10-31 последний опубликованный стабильный релиз VDA — `2024-12-16-windows11`. Установщик использует проверенные версии и SHA256, а не произвольный будущий `latest`: API зависит от сборки ОС. При новом релизе нужно проверить ABI и обновить таблицу и хеши в `oes-babl-win.ps1`.

У Windows 10-версии VDA нет необходимых CreateDesktop/RemoveDesktop. Публичный [IVirtualDesktopManager](https://learn.microsoft.com/en-us/windows/win32/api/shobjidl_core/nn-shobjidl_core-ivirtualdesktopmanager) тоже не предоставляет создание, переключение и удаление рабочих столов. Поэтому «универсального COM fallback» для этих операций здесь нет. Режим Required завершится понятной ошибкой; MonitorOnly оставит только изоляцию по монитору. Win32 CreateDesktop/SwitchDesktop относятся к другим объектам Windows и не заменяют виртуальные рабочие столы оболочки.

## Установка

1. Установите Chrome. Проверьте App Installer / winget:

   ~~~powershell
   winget --version
   ~~~

   Если команды нет, установите [App Installer](https://apps.microsoft.com/detail/9NBLGGH4NNS1), затем заново откройте PowerShell.

2. Получите полную папку проекта; запускайте **обычный** x64 PowerShell от своего пользователя:

   ~~~powershell
   git clone https://github.com/itisabyl/oes-babl.git
   cd oes-babl
   powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\install.ps1
   ~~~

   Для ветки с ещё не слитыми изменениями сначала переключитесь на соответствующую ветку. Можно скачать ZIP вместо использования Git. ExecutionPolicy Bypass относится только к этому процессу и не меняет политику системы.

3. Установщик проверяет ОС, скачивает подходящую DLL с проверкой PE/x64 и закреплённого SHA256, затем проверяет/устанавливает зависимости:

   ~~~powershell
   winget install --id=Microsoft.VCRedist.2015+.x64 -e
   winget install --id=VirtualDrivers.Virtual-Display-Driver -e
   ~~~

   Эти команды приведены для ручного восстановления; при нормальном запуске их выполняет установщик. Подтвердите UAC, если Windows запросит. Скрипт целиком повышать не требуется.

4. Если winget установил только управляющее приложение, откройте **Virtual Driver Control** и нажмите установку/включение драйвера, создайте один виртуальный монитор. Различные версии пакета VDD могут требовать этот шаг. Установщик проверяет наличие работающего PnP-устройства и возвращает ошибку, если установка драйвера осталась незавершённой.

5. В Windows → Система → Дисплей убедитесь, что физический экран основной, а VDD работает в режиме **«Расширить эти экраны»**, без дублирования. VDD должен поддерживать сохранённое разрешение; при необходимости добавьте его через VDD. Не изменяйте конфигурацию драйвера во время трансляции.

6. Откройте новое окно PowerShell:

   ~~~powershell
   & "$env:LOCALAPPDATA\oes-babl-win\oes-babl-win.ps1" -Help
   powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\tests\install.ps1
   ~~~

Приложение устанавливается в `%LOCALAPPDATA%\oes-babl-win`. Пользовательский PATH получает этот путь ровно один раз, с учётом регистра/концевого слеша. В `%APPDATA%\oes-babl-win\screen-size` записываются физические размеры основного экрана через Screen.PrimaryScreen.Bounds в DPI-aware контексте. Повторная установка обновляет файлы и размер, не добавляя копии PATH.

Код возврата установщика: 0 — завершено, 1 — ошибка/незавершённая установка, 3010 — требуется перезагрузка. Автоматической перезагрузки нет. После перезагрузки повторите установку и проверку. При сбое установки уже установленные системные зависимости автоматически не удаляются; повторный запуск продолжает настройку.

## Запуск

~~~powershell
oes-babl-win.ps1
oes-babl-win.ps1 -Url https://example.com -Size 1920x1080 -Profile 'Profile 1'
oes-babl-win.ps1 -Force -Verbose
oes-babl-win.ps1 -KeepProfile
oes-babl-win.ps1 -DesktopMode MonitorOnly
oes-babl-win.ps1 -DisplayName '\\.\DISPLAY2'
~~~

Если политика выполнения блокирует .ps1 или PATH в существующем терминале ещё старый:

~~~powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File "$env:LOCALAPPDATA\oes-babl-win\oes-babl-win.ps1"
~~~

| Параметр | Значение |
| --- | --- |
| -Url | Абсолютный HTTP/HTTPS URL; по умолчанию https://lms.astanait.edu.kz |
| -Profile | Имя каталога нового профиля; по умолчанию Default |
| -Size | Положительный WxH, до 16384 на измерение, из режимов VDD |
| -Force | Разрешить закрытие всех Chrome текущей Windows-сессии, включая принудительное завершение |
| -KeepProfile | Не удалять временный каталог; его путь выводится в терминале |
| -NoPreview | Отключить встроенный просмотр VDD на физическом мониторе |
| -DesktopMode Required | По умолчанию: создать отдельный рабочий стол через совместимую VDA |
| -DesktopMode MonitorOnly | Явно отключить автоматизацию рабочих столов; пользоваться текущим |
| -DisplayName | Выбрать конкретный **опознанный VDD** при нескольких виртуальных мониторах |
| -Help | Справка без проверки/запуска зависимостей |
| -Verbose | Диагностические сообщения PowerShell |

Приоритет размера: `-Size > OES_BABL_SIZE > screen-size > 1920x1080`. Повреждённый сохранённый размер даёт предупреждение и fallback; неверный явный параметр/переменная — ошибку.

Приоритет профиля: `явный -Profile > CHROME_PROFILE > Default`.

~~~powershell
$env:OES_BABL_SIZE = '1280x720'
$env:CHROME_PROFILE = 'Profile 1'
oes-babl-win.ps1
Remove-Item Env:OES_BABL_SIZE, Env:CHROME_PROFILE
~~~

Перед запуском сохраните работу в обычном Chrome. Если он ещё работает, скрипт попросит ввести ровно `YES`; `-Force` пропускает вопрос. Без подтверждения процессы не закрываются. Хотя свежему каталогу не мешает обычный профиль Chrome, эта проверка намеренно сохранена по требованиям проекта.

Скрипт выбирает VDD по адаптеру/идентификатору MttVDD или монитору MTT1337, никогда просто по признаку «второй экран». Несколько VDD требуют -DisplayName. Для включения/выключения выбранного дисплея используются функции Enable-VirtualDisplay / Disable-VirtualDisplay и ChangeDisplaySettingsEx. Глобальные DisplaySwitch /internal и DevCon не используются: они могут затронуть другие экраны, а отключённое PnP-устройство всё равно требует администратора.

Сначала проверяются режим дисплея, DLL и Chrome. Затем создаются временный профиль и рабочий стол, запускается Chrome. Аргументы экранируются, новые окна дополнительно перемещаются SetWindowPos. Chrome и потомки принадлежат отдельному Job Object. После закрытия последнего видимого окна фоновые процессы завершаются; ожидание не зависит от единственного PID.

При выходе/Ctrl+C скрипт закрывает свой Chrome, удаляет только созданный рабочий стол по GUID, возвращается на исходный, восстанавливает VDD и удаляет свой GUID-каталог. Ранее активный VDD остаётся активным с прежним размером; включённый скриптом отключается.

## Встроенный предпросмотр виртуального монитора

VDD не имеет физической панели. По умолчанию на основном физическом экране открывается окно предпросмотра, построенное на встроенных Windows Forms/GDI. Дополнительный просмотрщик не требуется. Кадры хранятся только в памяти и обновляются примерно восемь раз в секунду; фактическая частота зависит от разрешения и скорости машины.

Нажмите нужное место изображения: координаты клика переводятся на VDD, фокус получает Chrome, курсор возвращается в исходное положение. После клика печатайте и используйте горячие клавиши Chrome обычным способом. Поддерживаются одиночные клики левой/правой/средней кнопкой и прокрутка. Чёрные поля вокруг изображения не получают ввод. Окно просмотра удерживается в пределах основного экрана, чтобы не создавать рекурсивный захват.

Перетаскивание, точное двойное нажатие, сенсорный ввод и hover пока не реализованы. Для выделения текста используйте клавиатуру. Прокрутка зависит также от Windows-настройки прокрутки неактивных окон. Защищённое видео/HDR и некоторые аппаратные конфигурации могут показываться некорректно через GDI; проверьте предпросмотр до звонка. Нативные диалоги Chrome могут открываться отдельно.

Закрытие предпросмотра завершает сеанс и запускает очистку. Сначала остановите трансляцию. Если используете свой просмотрщик, задайте -NoPreview.

## Проверка изоляции: Google Meet и запись

1. До звонка отключите показ панели задач на остальных мониторах, включите «Не беспокоить», уберите закреплённые на всех рабочих столах окна. Проверьте, что VDD не зеркалирует физический экран.
2. Запустите лаунчер, войдите в сайт в свежем профиле. В Meet выберите «Весь экран», затем VDD по **содержимому предпросмотра**, не только по номеру: нумерация Chrome может отличаться от DISPLAY2.
3. Подключите второе устройство/участника для независимой проверки результата. Изображение должно содержать Chrome на VDD, без физических мониторов.
4. Откройте Блокнот на физическом мониторе **в том же активном виртуальном рабочем столе**. Двигайте его по физическому экрану: он не должен появляться у зрителя.
5. Негативный тест делайте только в тестовом звонке: перенесите Блокнот на VDD. Он появится у зрителя — это ожидаемый предел изоляции.
6. Для OBS или другого рекордера выбирайте отдельный VDD в Display Capture, а не весь объединённый рабочий стол. Запишите короткий ролик с действиями из п. 4, воспроизведите и проверьте каждый переход.
7. Остановите шаринг/запись, затем закройте все окна этого Chrome. Проверьте возврат рабочего стола и очистку.

Выбор источника захвата выполняет пользователь в системном/браузерном диалоге. Скрипт не может надёжно выбрать монитор за пользователя и не проверяет содержимое исходящей трансляции.

## Тесты и критерии приёмки

Из корня проекта в Windows PowerShell 5.1:

~~~powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\tests\run.ps1
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\tests\install.ps1 -SelfTest
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\tests\install.ps1
~~~

Каждый успешный скрипт выводит `Test passed.`, ошибка даёт exit 1.

- run.ps1: ParseFile всех PowerShell-файлов, BOM, справка в дочернем процессе, отсутствие VDD с подменой обнаружения, приоритеты настроек, отказ при неоднозначном/физическом мониторе, проверка ABI структур, реальный Job Object с безопасным дочерним процессом, защита удаления временных каталогов.
- install.ps1 -SelfTest: фикстуры валидатора установки и идемпотентность PATH. **Это не тест настоящей установки.**
- install.ps1 без флага: реальные установленные файлы, PATH, screen-size, хеш DLL, PnP VDD, endpoint дисплея, VC++, чтение текущего рабочего стола через VDA, где поддерживается.
- CI выполняет первые два набора. Установка драйвера, Chrome, переключение рабочих столов и звонок в CI не выполняются.

| Критерий | Действия и ожидаемый результат |
| --- | --- |
| 1. Чистая Windows 11 / идемпотентность | Установите дважды в тестовой системе, после каждого раза запустите tests/install.ps1; PATH содержит одну запись, размер обновлён. Проверьте сообщения UAC/перезагрузки. |
| 2. Chrome + VDD + рабочий стол | На поддерживаемой сборке запомните Win+Tab и размер VDD, запустите Required; появляется один новый стол и окно Chrome на VDD; закройте Chrome, исходное состояние возвращается. |
| 3. Захват только нужного монитора | Выполните сценарий Meet/рекордера выше с независимым зрителем. Окна вне VDD не видны; абсолютная защита от окон на VDD не обеспечивается. |
| 4. Тесты | Запустите оба скрипта без -SelfTest после установки; оба завершаются 0 и печатают Test passed. |
| 5. Документация | Пройдите установку, запуск, troubleshooting и восстановление по этому файлу на отдельной машине. |
| 6. BOM / синтаксис | Запустите tests/run.ps1 в PowerShell 5.1. Windows .ps1/.cs и эта документация UTF-8 BOM; Linux shell-файлы сохраняют исходное кодирование и shebang. |
| 7. Кодировка | Проверьте -Help и сообщения в обычной консоли. Пользовательские сообщения ASCII English; комментарии и README — UTF-8 BOM. |
| 8. Ctrl+C | В тестовом запуске остановите шаринг, вернитесь к терминалу через Alt+Tab на том же столе, нажмите Ctrl+C. Проверьте Chrome, Win+Tab, профиль и VDD. Повторите при ошибке старта/исчезновении дисплея. |
| 9. Нет VDD | Без драйвера запустите лаунчер; получите exit 1 с точной winget-командой. Автотест моделирует это без удаления установленного драйвера. |
| 10. Chrome уже открыт | Сохраните данные, запустите обычный Chrome; отказ от YES должен сохранить его; YES или -Force закрывают процессы текущей сессии и продолжают запуск. |

Дополнительно: два параллельных запуска (второй отклоняется), отрицательные координаты VDD, разные DPI, несколько VDD, неподдерживаемый -Size, окно Chrome в фоне, -KeepProfile, неизвестная сборка Windows. Для -KeepProfile проверьте сохранение каталога; при следующем запуске создаётся **новый** GUID, сохранённый каталог автоматически не переиспользуется.

## Troubleshooting

| Симптом | Причина | Решение |
| --- | --- | --- |
| winget is missing | Нет App Installer или старый терминал | Обновите App Installer и заново откройте терминал |
| VDD is not installed после winget | Установлен менеджер, но не сам драйвер | Virtual Driver Control → Install/Enable; повторите install.ps1 |
| VDD disabled / device error | PnP-устройство выключено, отсутствует VC++ или нужна перезагрузка | Исправьте устройство в диспетчере устройств от администратора, проверьте VC++, выполните запрошенную перезагрузку |
| No verified VDD endpoint | Нет созданного монитора, изменились идентификаторы драйвера | Создайте монитор в VDC; не подменяйте его произвольным физическим дисплеем |
| Several VDD displays | Несколько кандидатов | Выберите конкретный -DisplayName из сообщения |
| VDD overlaps/mirrors | Дублирование мониторов | Включите Extend и расположите мониторы без перекрытия |
| VDD does not advertise WxH | Режим отсутствует в драйвере | Добавьте его в VDD либо задайте поддерживаемый -Size |
| VDA version/hash / rejected operation | Windows обновилась, DLL повреждена либо ABI изменился | Обновите проект, повторите установку; временно используйте MonitorOnly с пониманием ограничений |
| Chrome не видно | Он находится на виртуальном мониторе без панели | Используйте встроенный предпросмотр без -NoPreview; проверьте режим VDD |
| Клики/клавиши не доходят из предпросмотра | Разные уровни привилегий либо нет фокуса | Запускайте лаунчер обычным пользователем; кликните именно изображение перед набором текста |
| Chrome закрылся при Win+Ctrl+стрелка | Защита от продолжения на другом столе | Не меняйте виртуальный рабочий стол во время сеанса |
| Chrome не выходит в фоне | Остались background-процессы | Лаунчер ожидает окна, затем завершает собственный Job; проверьте диагностическую ошибку |
| Profile cleanup failed | Файл удерживает антивирус или каталог содержит reparse point | Закройте связанный Chrome, проверьте точный указанный каталог, удалите вручную после проверки |
| Команда не найдена / scripts disabled | Старый PATH / execution policy | Запустите по полному пути через powershell.exe -ExecutionPolicy Bypass -File |
| Ошибка скачивания / SHA256 | Сеть, прокси либо заменён release asset | Повторите позже; при несовпадении хеша сверяйте upstream, не отключайте проверку |

## Восстановление и ограничения

**Обновления GPU/чипсета:** разработчики VDD рекомендуют удалить VDD перед крупным обновлением, затем установить заново. Возможен чёрный экран, если Windows назначит виртуальный дисплей основным.

Восстановление: откройте Windows Recovery → Troubleshoot → Advanced options → Startup Settings → Restart → F4 (Safe Mode). В диспетчере устройств раскройте Display adapters и удалите **Virtual Display Driver**, затем перезагрузитесь. Не удаляйте физический GPU. Если изображение ещё доступно, можно сначала вернуть физический экран через Win+P / настройки дисплея.

Обычный Ctrl+C обрабатывается finally. Принудительное завершение PowerShell в Task Manager, сбой Explorer или отключение питания не позволяют гарантировать finally: Job закрывает свой Chrome при завершении владельца, но рабочий стол/режим VDD/профиль могут остаться. После проверки остановки записи удалите оставшийся стол через Win+Tab, восстановите дисплеи в Windows Settings и удалите только нужный GUID-каталог из chrome-data. Скрипт не удаляет автоматически неизвестные каталоги прежних запусков.

Временный профиль может содержать приватные данные; -KeepProfile сохраняет их на диске, обычное удаление не является криптографическим стиранием. Не добавляйте профили, DLL и vda.json в Git. В репозитории предусмотрен .gitignore. Права наследуются от пользовательского LocalAppData.

План дальнейшей работы:

1. Пройти аппаратную матрицу Windows 10/11, версий VDD/Chrome, DPI и Google Meet с записью результатов; до этого не объявлять аппаратные критерии выполненными.
2. Аппаратно проверить встроенный предпросмотр, DPI и передачу ввода; расширить его перетаскиванием/hover и более быстрым захватом через Desktop Duplication.
3. Для широкой автоматизации Windows 10 поддерживать отдельный версионируемый COM backend или внешний обслуживаемый компонент; публичного универсального API для этих операций нет.
4. Для строгого исключения чужих окон выбирать «Окно Chrome» / «Вкладка Chrome» в Meet. При обязательном полном экране с гарантированной изоляцией нужна отдельная сессия/VM или другая архитектура; заданный набор VDD + виртуальный рабочий стол такой гарантии не даёт.
