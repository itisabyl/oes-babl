# oes-babl

Проект создан методом вайбкодинга — с помощью ИИ.

Запускает отдельный экран Xephyr на весь монитор и Google Chrome с существующим профилем внутри него. Chrome разворачивается как обычное окно: вкладки и адресная строка остаются видимыми.

Проект позволяет скрыть окна сторонних программ из полноэкранной записи или демонстрации экрана в Chrome. Для этого Chrome запускается внутри Xephyr, а источником захвата «Весь экран» выбирается именно экран Xephyr. Программы, открытые за пределами этого экрана, не попадают в запись или трансляцию.

По умолчанию открывается <https://lms.astanait.edu.kz>. Размер виртуального экрана определяется при установке и сохраняется для следующих запусков. Если монитор определить не удалось, используется 1920×1080.

## Windows

Нативная экспериментальная Windows-версия на PowerShell и Virtual Display Driver: [установка, запуск, тесты и ограничения](README-Windows.md).
При демонстрации «Весь экран» необходимо выбрать именно VDD-монитор. Полная изоляция уровня Xephyr не гарантируется; Windows 10 использует явно выбранный режим MonitorOnly.

### Установка и запуск в Windows

Нужны Windows 10 1809+/11 **x64**, Google Chrome, PowerShell 5.1+ и winget (App Installer). Откройте обычный PowerShell от своего пользователя:

```powershell
git clone https://github.com/itisabyl/oes-babl.git
cd oes-babl
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\install.ps1
```

Установка VDD и Visual C++ может вызвать запрос прав администратора. Если winget установил только **VDD Control**, откройте его и выполните установку самого драйвера. Создайте один виртуальный монитор, оставьте физический экран основным и выберите режим **«Расширить эти экраны»**. Затем повторите `install.ps1`. Перезагрузите Windows, только если установщик этого потребует.

Запуск после установки (работает без обновления PATH текущего терминала):

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File "$env:LOCALAPPDATA\oes-babl-win\oes-babl-win.ps1"
```

Откроется Chrome на VDD и окно предпросмотра на физическом экране. Кликните изображение, чтобы работать с Chrome; закрытие предпросмотра завершает сеанс. Если Chrome уже открыт, сначала сохраните работу: лаунчер запросит подтверждение его закрытия. Для Google Meet выбирайте **«Весь экран» → только VDD-монитор**.

Для Windows 10 и сборок Windows 11 без совместимой автоматизации рабочих столов используйте явно заданный режим:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File "$env:LOCALAPPDATA\oes-babl-win\oes-babl-win.ps1" -DesktopMode MonitorOnly
```

Другой сайт, размер и справка:

```powershell
& "$env:LOCALAPPDATA\oes-babl-win\oes-babl-win.ps1" -Url https://example.com -Size 1920x1080
& "$env:LOCALAPPDATA\oes-babl-win\oes-babl-win.ps1" -Help
```

Каждый запуск создаёт новый профиль Chrome; существующие входы и cookies не копируются. Все параметры, диагностика и восстановление описаны в [README-Windows.md](README-Windows.md).

## Требования Linux-версии

- Linux, Bash и Google Chrome (`google-chrome-stable` или `google-chrome`).
- Xephyr, Openbox, xauth, xprop, mcookie и flock.
- В Wayland-сессии нужен работающий Xwayland и переменная `DISPLAY`. В KDE Plasma и GNOME это встроено, а в niri обычно обеспечивается через `xwayland-satellite`.
- Необязательно: `python3` с `python-gobject` и `gtk3` — для автоматической двусторонней синхронизации текстового буфера обмена между хостом и виртуальным экраном Xephyr.
- Zsh и fish необязательны. Для Windows предусмотрен отдельный лаунчер; macOS не поддерживается.

В Arch Linux зависимости устанавливаются так:

```bash
sudo pacman -S --needed xorg-server-xephyr openbox xorg-xauth xorg-xprop util-linux python-gobject gtk3
```

Google Chrome устанавливается отдельно.

## Установка

```bash
git clone https://github.com/itisabyl/oes-babl.git
cd oes-babl
./install.sh
```

Установщик копирует скрипт в `~/.local/bin/oes-babl` и настраивает команду для Bash: сохраняет функцию в `~/.config/oes-babl/oes-babl.bash` (с учётом `XDG_CONFIG_HOME`) и добавляет её подключение в `~/.bashrc`. Если установлен Zsh, подключение добавляется в `${ZDOTDIR:-$HOME}/.zshrc`. Повторная установка обновляет функцию, не дублируя строку подключения. Если установлен fish, установщик также добавляет функцию `oes-babl` и автодополнение параметров в каталоги `functions` и `completions` fish.

Разрешение определяется по текущему монитору niri (через `niri` и `python3`), затем в KDE Plasma через `kscreen-doctor` (и `python3`), а затем через `xrandr`: основной активный монитор, а если основной не задан — первый активный. В niri и KDE Plasma сохраняется физическое разрешение с учётом поворота, без уменьшения из-за масштаба интерфейса. Если инструменты отсутствуют, монитор отключён или графическая сессия недоступна, установка продолжается с 1920×1080.

Размер записывается в `~/.config/oes-babl/screen-size` (или `$XDG_CONFIG_HOME/oes-babl/screen-size`). При смене монитора можно повторить `./install.sh` или запускать `oes-babl --auto-size` (`OES_BABL_SIZE=auto`). По умолчанию при отсутствии или повреждении файла настроек используется 1920×1080.

## Запуск

Сначала сохраните работу и полностью выйдите из обычного Chrome через **⋮ → Выход** (либо используйте флаг `--standalone` для запуска с отдельным профилем). Один каталог профилей нельзя одновременно использовать в двух экземплярах браузера. Если основной профиль выбран и Chrome продолжает работать в фоне, скрипт попросит завершить его.

В fish:

```fish
oes-babl
```

В Bash после установки откройте новый терминал или выполните:

```bash
source ~/.bashrc
oes-babl
```

Можно запустить напрямую из любой оболочки:

```bash
~/.local/bin/oes-babl
```

В Zsh после установки откройте новый терминал и выполните `oes-babl`.

Открыть другой сайт:

```bash
oes-babl https://example.com
```

Изменить размер экрана на один запуск (имеет приоритет над сохранённым) или определить его автоматически по активному монитору:

```bash
OES_BABL_SIZE=1920x1080 oes-babl
oes-babl --auto-size
```

Запустить Chrome с отдельным постоянным профилем (`~/.config/oes-babl/chrome-profile`), не закрывая основной браузер на рабочем столе:

```bash
oes-babl --standalone
```

Включить захват курсора и клавиатуры внутри Xephyr (переключается сочетанием `Ctrl+Shift` — полезно в KDE Plasma, чтобы случайное движение мыши в левый верхний угол не вызывало `Overview` и потерю фокуса на прокторинге):

```bash
oes-babl --grab
```

Задать раскладки клавиатуры внутри виртуального экрана:

```bash
OES_BABL_LAYOUT=us,ru,kz oes-babl
```

Автоматический выбор учитывает текущую сессию (`XDG_CURRENT_DESKTOP` или `XDG_SESSION_DESKTOP`): в KDE читаются `kxkbrc` и комбинация переключения раскладки из `kglobalshortcutsrc`, а в niri — строки `layout` и `options` из основного `config.kdl`. Если в `Options` указаны дополнительные параметры XKB без `grp:*` (например, `scrolllock:mod3`), переключатель раскладки автоматически добавляется к ним. Оставшиеся от другой сессии файлы не используются. Если раскладки не найдены, читаются настройки X11, затем используется `us,ru`. Сложные настройки niri с `include` можно задать явно через `OES_BABL_LAYOUT`.

Сочетание переключения можно задать отдельно (по умолчанию используются найденные настройки или `Alt+Shift`):

```bash
OES_BABL_XKB_OPTIONS=grp:win_space_toggle oes-babl
```

Пустое значение `OES_BABL_XKB_OPTIONS=''` отключает дополнительные опции XKB.

Выбрать конкретный профиль Chrome:

```bash
CHROME_PROFILE="Profile 1" oes-babl
```

Имя каталога профиля можно посмотреть в поле **Profile Path** на странице `chrome://version`: например, `Default` или `Profile 1`.

Скрипт использует обычный каталог данных Chrome, учитывая `CHROME_USER_DATA_DIR`, `CHROME_CONFIG_HOME` и `XDG_CONFIG_HOME`. Профили, cookies и пароли остаются на вашем компьютере. Не добавляйте каталог профиля в репозиторий.

## Запись экрана и завершение

Открывайте сайт записи внутри Chrome, запущенного через `oes-babl`. При выборе «Весь экран» проверяйте предпросмотр: он должен показывать экран Xephyr. Выбор источника зависит от версии Chrome и механизма захвата; скрипт не создаёт дополнительный выход монитора в niri.

Закройте Chrome, чтобы завершить процесс и закрыть виртуальный экран (флаг `--disable-background-mode` отключает удержание фоновых процессов при закрытии окна). При прерывании скрипта он отправляет запущенному Chrome сигнал завершения, затем закрывает Openbox и Xephyr.

По умолчанию Xephyr запускается с `-no-host-grab`, чтобы можно было свободно перемещать курсор и пользоваться хоткеями композитора (для удержания курсора используйте `--grab` или `OES_BABL_GRAB=1`). При наличии `python3` и `PyGObject` (`Gtk 3.0`) автоматически запускается фоновый мост буфера обмена между хостом и Xephyr; чтобы полностью изолировать буфер обмена, укажите `--no-clipboard` или `OES_BABL_CLIPBOARD=0`.

Временные файлы авторизации удаляются при завершении. Xephyr не слушает TCP и использует отдельный cookie X11.

Каталог блокировки создаётся с правами `0700` в приватном `XDG_RUNTIME_DIR` или `/tmp/oes-babl-UID`. Если существующий каталог имеет небезопасные права, другого владельца или является символической ссылкой, запуск останавливается. Скрипт не меняет права такого каталога; файл блокировки также не может быть символической ссылкой.
